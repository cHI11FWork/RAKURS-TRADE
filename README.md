# RAKURS TRADE — корпоративний сайт

Лендінг + адмін-панель для інженерної компанії RAKURS TRADE (автономне енергозабезпечення,
блискавозахист та заземлення, Defense & Security).

Стек: Next.js 16 (App Router) + TypeScript + Tailwind CSS v4 + Supabase (база даних, авторизація,
сховище файлів) + Vercel (хостинг).

## Як це влаштовано

- **Публічний сайт (`/`)** — повністю керується з адмінки: заголовок і фон банера, переваги,
  картки напрямів з пунктами списку, блок "Про компанію" з показниками, контакти та форма заявки.
- **Адмінка (`/admin`)** — захищена входом (Supabase Auth). Дозволяє додавати, редагувати,
  приховувати/показувати та видаляти будь-який блок контенту без втручання в код.
- **База даних** — Supabase Postgres з Row Level Security: читати контент може будь-хто, а
  редагувати — лише залогинений адміністратор.

## Перший запуск

### 1. Налаштувати базу даних Supabase

Відкрити SQL Editor у проєкті Supabase та по черзі виконати два файли з папки
[`supabase/migrations`](supabase/migrations):

1. `0001_init.sql` — створює всі таблиці, політики безпеки (RLS) та сховище для зображень.
2. `0002_seed.sql` — заповнює сайт початковим текстом (можна одразу редагувати з адмінки).

### 2. Створити акаунт адміністратора

У Supabase Dashboard → **Authentication → Users → Add user** створити користувача з email і
паролем, якими власник сайту буде заходити в `/admin`. Публічна реєстрація в адмінці вимкнена —
акаунт створюється тільки вручну в Dashboard.

### 3. Змінні середовища

Скопіювати `.env.example` → `.env.local` і вказати дані свого проєкту Supabase
(Project Settings → API):

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
```

Використовується лише публічний (`anon`/`publishable`) ключ — секретний ключ (`service_role`)
проєкту не потрібен і ніде в коді не використовується.

### 4. Встановити залежності та запустити

```bash
npm install
npm run dev
```

Сайт: http://localhost:3000 · Адмінка: http://localhost:3000/admin

## Деплой на Vercel

Проєкт розгорнуто на Vercel. У налаштуваннях проєкту (Settings → Environment Variables) мають
бути ті самі дві змінні, що і в `.env.local`.

## Структура

```
src/app/                  публічні сторінки (App Router)
src/app/admin/(auth)      сторінка входу в адмінку
src/app/admin/(dashboard) захищені сторінки адмінки + server actions для кожного розділу
src/components/site/      компоненти публічного сайту
src/components/admin/     перевикористовувані елементи адмінки (перемикачі, кнопки, аплоад фото)
src/lib/                  Supabase-клієнти, типи, запити до бази
src/proxy.ts              захист /admin — редірект на логін, якщо користувач не авторизований
supabase/migrations/      SQL-схема бази даних і початковий контент
```
